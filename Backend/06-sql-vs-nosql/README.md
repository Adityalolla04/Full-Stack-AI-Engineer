# SQL vs NoSQL

[Back to Backend](../README.md) · [Your practice space](practice/README.md)

## In simple words

Choose storage by data relationships, access patterns, and consistency needs.

## What to understand

Relational stores support structured relationships and constraints; document/key-value/other stores optimize different workloads. These labels do not determine every transaction guarantee.

## Think through this example

Study sessions and users fit relational constraints; a flexible document payload may fit a document model.

## Common mistake

Choosing a database based only on popularity or the claim that NoSQL always scales better.
