# REST APIs

[Back to Backend](../README.md) · [Your practice space](practice/README.md)

## In simple words

Model an API around resources and predictable operations.

## What to understand

Use consistent URLs, methods, representations, status codes, and error shapes. Idempotency describes repeated effects, not identical responses.

## Think through this example

A study-session resource can be created, retrieved, updated, and deleted using one coherent contract.

## Common mistake

Using GET for state-changing operations.

## Practice yourself

Design a study-session API contract with normal and failure responses.
