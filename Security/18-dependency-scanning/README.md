# Dependency Scanning

[Back to Security](../README.md) · [Your practice space](practice/README.md)

## In simple words

Dependency scanning identifies known risks in software components and their versions.

## What to understand

Track direct/transitive dependencies, lockfiles, advisories, reachability, remediation, and review exceptions.

## Think through this example

A vulnerable transitive package may arrive even when your own source has not changed.

## Common mistake

Assuming no scanner findings means no exploitable flaws.

## Practice yourself

Plan scan frequency, triage, update testing, and a time-bounded exception process.
