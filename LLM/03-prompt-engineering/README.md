# Prompt Engineering

[Back to LLM](../README.md) · [Your practice space](practice/README.md)

## In simple words

A prompt specifies the task, relevant context, constraints, and expected result.

## What to understand

Make success observable; compare prompts on a fixed evaluation set rather than one appealing answer.

## Think through this example

A request for cited answers and explicit uncertainty is more testable than a vague request to be helpful.

## Common mistake

Assuming wording alone provides security or guaranteed correctness.

## Practice yourself

Write three prompt variants in your notes and define how you would evaluate them.

Write your own implementation in `practice/` when ready. No solution or starter code is supplied.

## Recall check

- Explain the concept without reading the note.
- Explain why it fits the example and when you would choose something else.
- Describe one boundary or failure case before implementing.
